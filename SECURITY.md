# Security reports

Please use this repository's GitHub **Security → Report a vulnerability** flow for sensitive reports. If private reporting is unavailable, open an issue asking for a private reporting channel without including exploit details or credentials.

The project is an initial release. Do not describe it as independently audited. Reports about policy bypass, credential disclosure, destination control, and management authorization are particularly useful. Include a minimal reproduction using generated credentials.

Never attach real API tokens, infrastructure passwords, private keys, or secret-store responses. Rotate any credential exposed while investigating.
